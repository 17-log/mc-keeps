# McKeeps 传播性调研：人格测试、原创像素视觉与照片手帐

调研日期：2026-10-22。本文整理公开页面与文章，为现有 **mc-keeps** 仓库的优化提供依据。仅保留公开来源、可见事实、访问限制与产品判断，不附原始抓取数据、登录资料或个人记录。本文不是发布公告，不表示公开网站已经更新。

## 调研判断

人格测试适合作为手帐的轻入口：用户用几个生活选择得到一个容易认领的称号，分享后让朋友先看结果、再测自己，最后将一个小任务接回真实照片与日期。值得借鉴的是自我表达、具象结果和朋友回应，不是给食物贴上四个字母就能获得传播。

公开案例已经覆盖程序员人格、咖啡人格、食物人格和像素食品测试；麦当劳也有产品对应人格的历史内容。因此，McKeeps 的差异应落在 **原创生活情境 → 可解释的像素结果 → 朋友偏好对照 → 有年月日的照片手帐**。这是一项产品判断，效果需要在真实使用中验证，不能从案例播放量直接推导增长。

当前人格源码的规则与隐私边界见 [personality.md](personality.md)，同仓库后续工作与内容方案见 [workbuddy-optimization.md](workbuddy-optimization.md)。这两份文档中的具体实现说明，优先于早期研究阶段的候选命名与轴设计。

## 方法与证据边界

- 对抖音视频页、哔哩哔哩视频页和小红书官方作品频道进行了只读浏览，公开搜索索引与可访问文章用于补充背景。
- 没有绕过登录、验证码、平台安全页或原站访问限制；未登录状态下无法完整观看的视频，不表述为已看完。
- 视频播放、点赞和作品“累计使用”是页面在采集时显示的累计值，不是本项目的数据，不同平台的口径不能直接比较。
- 没有核实各测试的完整算法、题库、结果分布、分享转化、用户去重或推广成本。下文明确区分已见事实和设计推断。
- 样本来自可公开访问的案例，不构成全平台热度排行，也不能证明某个玩法在调研当天仍是热点。

## 借鉴与差异：现有仓库怎样承接

| 可借鉴机制 | McKeeps 中的承接 | 明确边界 |
| --- | --- | --- |
| 短测试降低首次体验成本 | 8 道原创生活情境，四条轴，每轴两题；无需先传照片或连接订单 | 娱乐偏好表达，不是科学 MBTI 或心理诊断 |
| 给熟悉行为一个容易认领的名字 | 16 种原创称号，如“晚风独享家”“落日收藏家”“生活彩蛋家”，配原创像素食物 | 不宣称人格优劣、稀有度或准确率 |
| 结果卡本身就是内容 | 角色、短句、四轴解释、PNG 与同一结果二维码 | 生成图片或复制链接不等于真实分享成功 |
| 朋友能继续参与 | 结果深链先看分享者卡片，再自测，逐轴对照共同点与不同点 | 不输出关系匹配百分比；不是多人同步协作系统 |
| 让一次测试有后续生活内容 | 小任务打开原手帐草稿，用户确认餐品、日期和照片后保存 | 不自动把建议餐品当成消费，不自动写入日历 |
| 食物信息与个人经历结合 | 原有本机只读 MCP 可辅助订单事实，照片与文字由用户补充 | MCP 不参与人格评分，测评不需要 Token；订单仍须本人确认 |

目前采用的四条轴为 **同行方式（独享 / 搭子）、小事仪式（随性 / 仪式）、口味探索（经典 / 探索）、回忆习惯（当下 / 收藏）**。评分公开可复算；50 为混合偏好。完整公式、16 个名称、深链和本地存储说明见 [personality.md](personality.md)。

## 后续建议与待测量问题

**已形成的产品路径：**8 题 → 原创人格结果 → 结果深链或含 QR 的 PNG → 好友自测对照 → 原手帐草稿 → 用户确认后存入日期。当前源码已包含这条衔接；能否带来更多分享与持续记录，仍需实际使用检验。

**后续候选，尚不等于已实现：**基于自愿选择记录生成“本周手帐卡”；下班、独处、秋日或节日的原创内容包；更丰富的像素小场景。周记应说明来自几条记录，避免从照片、订单或消费金额推断稳定人格或健康状态。

**指标尚未接入埋点。**建议先定义测试开始 / 完成、导出 / 复制链接成功、结果深链打开 / 接收者完成、草稿打开 / 手帐保存这几步的事件口径，再考虑次周是否继续记录。不要把按钮点击当实际传播，也不要把访问量当独立用户或社交分享人数。接入统计前应说明采集范围，不收集答案、照片、日记正文和订单作为分析参数。

公开分享需要部署兼容版本的 HTTPS 页面。配置中的目标入口为 <https://17-log.github.io/mc-keeps/#persona>；本机能生成链接并不代表该地址已更新。发布状态应以实际部署与公开访问检查为准。
